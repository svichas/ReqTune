Features

Built for everyday web development

Point a frontend at staging, send a token to localhost, flip a feature flag or turn on debug tracing, without a proxy or a rebuild.

  • Groups

    Pair URL patterns with the headers to send, and switch each group on or off.

  • Wildcard patterns

    *.example.com/api/*, localhost:3000, /graphql and more.

  • Instant and native

    Changes apply as you type; a URL pattern once you leave its field. Chrome sets the headers itself, with no JavaScript in the request path.

  • URL patterns or tabs

    Target URLs, or send a group's headers on every request from the tabs you pick.

  • Priority you control

    When groups set the same header, the one higher in the list wins.

  • Screen-share safe

    Authorization, Cookie and other token-like values show as dots until you reveal them.

  • Comfortable editing

    Header name suggestions, duplicate groups, undo deletes, and Enter to add a row.

  • Side panel or full page

    The panel stays open while you browse. Open a full page when long tokens need more room.

  • Private

    Everything stays in local extension storage. ReqTune makes no network requests and collects nothing.

Patterns

Patterns that read like URLs

[scheme://]host[:port][/path], where * matches any characters.

  • In the host, * never crosses a /, so example.com can't match example.com.evil.com.
  • No path means the whole site. A path must match in full; the query string is ignored unless the pattern contains ?.
  • Leave out default ports (:80, :443). Chrome removes them from URLs, so they never match.
PatternMatches
example.comEvery URL on example.com, on any scheme, port and path
*.example.comexample.com and all of its subdomains
api.example.com/v1/*Everything under /v1/ on that host
localhost:3000Only port 3000
https://example.com/*HTTPS requests only
/graphqlThat path on any host
example.com/search?q=*Paths whose query string matches too

How it works

Chrome does the heavy lifting

ReqTune turns your groups into declarativeNetRequest rules, so Chrome itself sets the headers. No proxy, no content scripts, no JavaScript in the request path.

  1. Side panelYou edit groups, in React and Mantine
  2. chrome.storage.localGroups are saved on your device
  3. Service workerTurns your patterns into rules
  4. declarativeNetRequestmodifyHeaders rules, swapped atomically
  5. Matching requestsChrome sets your headers
Compiled, not interpreted
Each URL pattern compiles to an anchored regex, and group order becomes rule priority. In a group that appends to a header, patterns that can match one URL share a rule, so each append happens once.
Atomic updates
Rule sets are swapped in one step, so edits never leave them half-applied. Rules cover every resource type, page navigations included.
Tabs, too
A group that targets tabs becomes a session rule with a tabIds condition and no URL filter. Tab picks last until Chrome restarts.

One-click install, with automatic updates from Chrome.

Add to Chrome

From a release

  1. Download the zip from the latest release and unzip it.
  2. Open chrome://extensions and turn on Developer mode.
  3. Click Load unpacked and pick the unzipped folder.
Download latest release

From source

Needs Node.js 22.12 or later.

git clone https://github.com/svichas/ReqTune.git
cd ReqTune
npm install
npm run build

Then load the dist/ folder the same way.
